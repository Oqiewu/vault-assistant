# 0005 — Не контейнеризировать всё приложение

**Статус:** принято — 2026-09-13

## Контекст

Рассматривался вариант завернуть весь проект в Docker (app + Ollama), для этого потребовалось бы пробросить Obsidian vault (`C:\Users\Игорь\Documents\Personal`) в контейнер через volume.

## Решение

Контейнеризируем только LLM inference (Ollama, см. `docker-compose.yml`). Python-код (`chunk_vault.py`, `embed.py` и далее) работает нативно на хосте через venv, обращается к vault напрямую с диска и к Ollama по HTTP (`localhost:11434`).

## Обоснование

- Vault содержит не только заметки проекта, а весь личный Obsidian vault (CV с реальными данными, личные заметки, рабочие клиентские материалы) — пробрасывать его целиком в контейнер избыточно и нарушает принцип наименьших привилегий.
- Индустриальная практика: инструменты с широким доступом к файлам пользователя (Cursor, Continue.dev, Claude Code) работают как нативные процессы на хосте, не в контейнерах. Контейнеризация используется для изолированных сервисов с узким API (inference, векторные БД), а не для слоя, которому нужен произвольный доступ к файловой системе пользователя.

## Последствия

Векторная БД (см. [0003](0003-no-vector-db-yet.md)), если будет добавлена, тоже по умолчанию рассматривается как отдельный контейнеризированный сервис с узким API — не повод пересматривать это решение.
